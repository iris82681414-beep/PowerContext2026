# MiniMax 工程上下文：续借规则

**当前交付状态：MiniMax 真实改码及本地、Linux 验收完成，尚未取得平台正式分数。**

业务缺口是会员在没有预约时应续借 21 天，基线代码却返回普通读者的 14 天。原始三项测试包含这一失败，以及普通读者、已有预约两组回归行为。测试文件在本轮验证期间保持不变。

`sdd.py ingest` 将规格、代码和测试写入专用 seekdb 数据库的 `engineering_docs` 表，正文建立全文索引。`prepare renewal` 对三类资料分别执行实际的 `MATCH ... AGAINST` 查询，返回正文、路径、SHA-256 及查询记录。无关盘点规格作为干扰资料，不会被续借任务检索选中。修改规格副本后重新导入，返回的新正文和摘要必须同步变化。

PowerContext 1.2.0 的 builtin runtime 使用 SQLite 保存任务完成项、下一步及验证结果。独立的 `remember` 和 `prepare` 进程通过同一数据库路径和任务 scope 复用状态，并核对记忆版本引用。seekdb 承担工程资料检索，PowerContext 承担工程进度的持久化与恢复。

Python 3.12 的完整依赖固定在 `requirements.lock`。本轮修正了仅安装基础 PowerContext 包导致缺少 `opentelemetry` 的真实启动失败；该失败与业务基线失败分别保留，不能相互替代。`validate_context.py` 从全新记忆状态检查导入、三类检索、业务基线失败、独立进程恢复、规格更新和原规格恢复，保存版本、源码摘要、每个命令的退出码及原始输出。11 月 6 日分别在 macOS Python 3.12.14 和 Linux x86_64 Python 3.12.3 的干净环境、真实 seekdb 1.4 上运行完成，材料见 `evidence/context-20261106/` 和 `evidence/context-linux-20261106/`。两次运行的核心源码和依赖锁文件摘要一致。

`request_patch.py` 接收实际检索上下文，向指定区域的官方 MiniMax 接口请求完整业务模块提案。模型须显式指定；凭据仅来自进程环境。记录包括请求正文、响应 ID、返回模型、用量及内容摘要，不保存密钥或推理内容。提案须经审阅后再应用，保留前后快照和差异，使用同一份测试验证目标行为及回归，再将结果写回 PowerContext 并重读。

11 月 6 日通过官方 MiniMax Agent 网页、页面明确选择的 M3.1-Flash 实际请求完成了改码。原始请求附件包含真实检索的三类资料与已恢复的 PowerContext 记忆。初次无余额请求失败；领取账户当日签到积分后，原请求重试成功。生成代码逐字应用到 `fixture/loan.py`，原始工程保留在 `baseline/`。两处测试文件 SHA-256 相同；修改前会员案例真实失败，修改后同三项测试在本地及 Linux 全部通过。

最新 Linux 验收重新执行了上下文导入、规格更新和恢复；随后运行修改后的测试，写入“已应用 MiniMax 改码、三项测试通过”的新状态，导入修改后源码，再通过两个独立 `prepare` 进程读取新代码摘要和相同的记忆版本引用。源码与锁文件摘要逐项核验。证据位于 `evidence/model-web-20261106/`：`validation.json` 关联真实网页模型、请求、截图、应用摘要、测试及 `linux-run/summary.json`。未包含凭据、浏览器会话或模型推理内容；模型自述的测试结论与实际运行证据分开。失败的 Qoder MiniMax 模型入口不被当作成功调用。

`validate_context.py` 仍是独立的上下文检查工具，默认使用原始 `baseline/`，不会再次调用模型；其中的模型调用状态为 false 仅表示该命令自身不调用模型。完整任务结果以上述最新组合验收为准。正式提测尚未完成，本地验收不换算成比赛分数。
